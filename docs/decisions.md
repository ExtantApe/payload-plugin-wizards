# Decisions

Dated decisions for this repo, newest last.

- 2026-11-10: created from the standard repo starter kit.

- 2026-11-10: name approved by the owner on 2026-11-10 (Wizards, collection `guided-steps`, from the platform team's answers for the kit packing station). MIT, public from its first push. Design in [architecture/0001-design.md](architecture/0001-design.md).
- 2026-11-10: answers are checked on the server against the current steps' content hashes before an owner acts, so a client can't skip a gate by posting directly, and the record says which wording was confirmed.
- 2026-11-10: component choices where the design was silent: focus moves to each new step's heading but not on first load; a chosen answer shows "(chosen)" and aria-pressed, not color alone; if `onFinish` fails, an alert says so and the buttons come back for a retry.
- 2026-11-10 (security read of 4898f71): a group of steps with no active step fails `answersFor` (`noSteps`), so an emptied or unseeded safety group never passes. The content hash is no longer stored: it's worked out per locale when a step is read and covers the stop message, video and captions (id and updatedAt). The record carries the locale and each question as read. Duplicate option values, a non-video video, non-WebVTT captions and a group used twice in a flow are refused. No withdraws an earlier Yes in the component. Test uploads go to a temp folder (`media/` is ignored).

- 2026-11-26: optional `scope: { where: ({ req }) => Where | Promise<Where>, indexWith?: string[] }`, shipping as 0.1.1, ruled by the maintainer in these words:
  - "Unset, everything behaves exactly as in 0.1.0, with a test that proves it."
  - "Fail closed. If where throws, or returns anything other than a non-empty plain object, the call refuses. A host that wants every site leaves scope unset."
  - "flowSteps and answersFor take an optional req. With scope set and no req, they refuse. Neither ever falls back to all sites. The scope is ANDed with the existing flow and active filters and never replaces them."
  - "Collection access: read, update and delete AND the scope where with what the rules already allow. ... The plugin's own overrideAccess: true reads ... apply the scope themselves."
  - "Writes: refuse a create or update that would leave the step outside the caller's scope, including an update that moves a step out of it."
  - "indexWith adds the host's site field(s) to that unique index. Document that the host adds the field itself."
  - "The 'group with no active step' refusal runs inside the caller's scope ... The start-up checks ... stay config-wide."
- 2026-11-26 (review of the first build): the write check runs in `beforeChange` on the merged document, before the write, and never relies on a rollback, because SQLite by default and standalone Mongo have no transactions. Deletes are scoped in `beforeDelete`. "At every depth, refuse empty and/or arrays and operator objects that are empty or have no keys"; a deliberate match-all such as `{ id: { exists: true } }` is the host's responsibility. Media is looked up as the caller (`overrideAccess: false`, with `req`), in the file-type check and in `flowSteps`. Out-of-scope refusals are 403s, and a start-up warning appears when `scope` has no `indexWith`. Tests run on Mongo (replica set and standalone) and SQLite (default and with transactions). `answersFor` answers `noScope` (`ok: false`) when the scope refuses; `@payloadcms/graphql` is a dev dependency for the GraphQL test; the collection has no versions, so there is nothing to scope there. Choices of ours: the supported operators are a fixed list so the in-memory check can be exact, and anything else is refused.
- 2026-11-27: a step whose question, stop message (gate or choice) or any option label is blank in the effective locale is refused on every path, failing closed: left out of `flowSteps` and named in `blank`, `blankStep` from `answersFor`, and an alert with no answer in `<Wizard>`. Blank means missing, empty, only spaces, or not a string. Fallback-on reads keep showing the default language's text. Choices of ours: the step is left out rather than shown, so no blank screen reaches a page; the save check also refuses spaces-only questions and labels; a draft still needs a question and stop message to save, as before for the stop message.
- 2026-11-27 (review of the blank-step change): text counts only if, after removing `\p{Default_Ignorable_Code_Point}` and U+2800, at least one `\p{L}`, `\p{N}`, `\p{P}` or `\p{S}` remains. It is a positive rule, the same at save and at read, so new invisible characters fail closed. An empty locale given to `answersFor` records the default language.
